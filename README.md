# OpenBand DAW

**A lightweight, open-source digital audio workstation for the browser and the desktop.**

https://github.com/user-attachments/assets/04b794ce-3b1e-41b3-a495-dfae4dd66d8b

<p align="center"><sub>40-second demo: synth tracks, the piano roll and a live guitar take through the amp simulator (<a href="docs/openband-daw-demo.mp4">docs/openband-daw-demo.mp4</a>). <a href="https://github.com/http-felipe/openband-daw/releases/latest">Download the latest release</a>.</sub></p>

OpenBand lets you sketch and record music: arrange tracks on a timeline, play and edit synthesised instruments, run a guitar through an amp simulator and export the result to WAV. It is written in TypeScript on top of the Web Audio API and AudioWorklets, runs in any modern browser, and ships as a desktop app for Windows, macOS and Linux via Electron.

Every sound is generated by code. There are no sample libraries, recorded impulse responses or third-party presets in this repository.

## Features

### Arrange and edit
- **Multitrack timeline** drawn on Canvas, with MIDI and audio clips you can move, resize, duplicate, **split** and **rename**. Split parts are numbered automatically (*Take 1* → *Take 1.1*, *Take 1.2*, …).
- **Cycle region**: drag on the ruler to set it. Zoom with ⌘/Ctrl + scroll and scroll horizontally with Shift + scroll.
- **Per-track mixer**: mute, solo, record-arm, volume, pan, peak meter and **automation lanes** for volume and pan.
- **Piano roll** for the selected MIDI clip: draw, move, resize and delete notes, multi-select, quantise, transpose, set velocity, and named drum lanes.
- **Undo/redo** for every edit, plus local autosave.

### Instruments: 6 engines, 61 presets, all synthesised
Pick a sound from the **+ Instrument** menu, grouped into Keys, Organ, Guitar & Strings, Bass, Mallets and Synth.

| Engine | Technique | Sounds |
| --- | --- | --- |
| **Piano & Mallets** | Modal synthesis: decaying resonant modes. The piano model uses stiff-string inharmonicity, hammer-position filtering, two detuned strings per key and a long aftersound | Grand (normal, bright, mellow), upright, marimba, vibraphone, kalimba, music box, steel drum, glockenspiel |
| **Plucked Strings** | Extended Karplus–Strong with pick position, loss filtering and a body resonance | Acoustic, nylon and clean-electric guitar, muted guitar, picked bass, harp, koto, banjo, mandolin |
| **Tonewheel Organ** | Nine drawbars combined into one waveform per voice, percussion, key click, vibrato and a rotary speaker that ramps between speeds | Jazz, rock, gospel, church, flute, reed, bright lead |
| **Subtractive Synth** | Two oscillators, resonant low-pass with its own envelope, ADSR and vibrato | Analog, supersaw and square leads; sub, acid, reese and sine basses; strings, brass, pads, choir, pluck, chiptune |
| **FM Synth** | Two-operator FM with a decaying index and an optional fast "tine" modulator | Electric piano, FM piano, clavinet, harpsichord, toy piano, tubular bells, brass, pad, bass |
| **Drum Machine** | Synthesised one-shots: pitch-swept kick, noise snare, clap, metallic hi-hats with choke, toms, rim, crash | Boom, Tight, Rock, Trap, House, Electro, Brushes and Lo-Fi kits |

### Effects and amp simulation
- **10 insert effects** per track and on the master bus: Gain, 3-band EQ, **Drive** (AudioWorklet with 2× oversampling; Soft, Hard, Tube and Fuzz curves), **Cabinet** (filter voicings or synthetic impulse responses), Delay (free or tempo-synced), convolution Reverb with procedurally generated impulse responses, Compressor, stereo **Chorus**, **Tremolo** and **Phaser**.
- Effects can be reordered, bypassed and tweaked in real time.
- **8 level-matched amp chains** for guitar and bass: Clean Combo, Clean Chorus, Surf Tremolo, British Crunch, High-Gain Lead, Fuzz Box, Phased Funk and Bass Amp.
- A **safety limiter** on the master bus keeps the output from clipping.

### Recording and input
- **Audio input** from any audio interface or microphone. Choose the device and the input channel; each channel has its own level meter so you can find your instrument. The choice is remembered on this computer.
- **Live monitoring** through the track's effects, for playing guitar through the amp simulator.
- **Recording** of audio and MIDI:
  - Takes are drawn in real time as you record.
  - An optional 1- or 2-bar count-in plays the metronome before recording starts.
  - Audio is captured as uncompressed PCM by an AudioWorklet and aligned to the beat using the browser's reported input and output latency.
  - MIDI recording supports overdub inside the cycle region.
- **MIDI controllers** over USB (Web MIDI API), including the sustain pedal, plus a playable on-screen keyboard.
- **Chromatic tuner** for the selected input, with a ±50-cent needle, reference strings for standard, Drop D and half-step-down guitar and 4- and 5-string bass, and an adjustable A4 reference (415–466 Hz).

### Projects and export
- Save and open projects as a single JSON file (`*.obproj.json`). Recorded audio is embedded, so one file holds the whole song. The format is documented in [docs/PROJECT_FORMAT.md](docs/PROJECT_FORMAT.md).
- **Export to WAV** with an offline render that runs faster than real time and sounds exactly like playback.

## Download

Desktop installers are attached to each release on the repository's **Releases** page.

| Platform | File |
| --- | --- |
| Windows 10/11 (x64) | `OpenBand-DAW-Setup-<version>-x64.exe` (installer) or `OpenBand-DAW-Portable-<version>-x64.exe` (no installation) |
| macOS, arm64 | `OpenBand-DAW-<version>-mac-arm64.dmg` |
| macOS, Intel | `OpenBand-DAW-<version>-mac-x64.dmg` |
| Linux (x64) | `OpenBand-DAW-<version>-linux-x86_64.AppImage` |

The installers are **not signed with a paid code-signing certificate**, so your operating system will warn you the first time:

- **Windows**: SmartScreen shows *"Windows protected your PC"*. Click **More info → Run anyway**.
- **macOS**: the app carries an ad-hoc signature, and macOS reports that it can't verify the developer. Open **System Settings → Privacy & Security** and click **Open Anyway**, or right-click the app and choose **Open**.
- **Linux**: make the AppImage executable (`chmod +x OpenBand-DAW-*.AppImage`) and run it.

## Run from source

**Requirements:** Node.js 18 or newer and npm. A Chromium-based browser (Chrome, Edge, Brave, Arc) is recommended. Firefox works too; Safari has no Web MIDI support.

```bash
git clone https://github.com/<your-user>/openband-daw.git
cd openband-daw
npm install
npm start
```

`npm start` opens the app at http://localhost:5173. Browsers only allow audio after a user gesture, so click anywhere in the page before pressing play.

| Script | What it does |
| --- | --- |
| `npm start` / `npm run dev` | Development server with hot reload |
| `npm run build` | Type-check and production build into `dist/` |
| `npm run preview` | Serve the production build |
| `npm test` | Unit tests (Vitest) |
| `npm run typecheck` | TypeScript type check only |
| `npm run desktop` | Build and open the Electron desktop app |
| `npm run test:desktop` | Smoke test: start the desktop app hidden, check the UI and audio engine load, then exit |
| `npm run dist` | Build installers for the current OS into `release/` |
| `npm run dist:win` / `dist:mac` / `dist:linux` | Build installers for one OS (Windows installers can be built on macOS) |

## Using OpenBand

### Play an instrument
1. Click **+ Instrument** and pick a sound. A new track is created with an empty 4-bar clip.
2. Play it with the **on-screen keyboard** at the bottom (use **− / +** to change octave) or with a **USB MIDI keyboard**.
3. Change the sound in the **Instrument** tab: choose an engine, pick a preset and adjust its controls. Double-click a control to reset it.

The keyboard plays the selected track. If any MIDI tracks are record-armed (**R**), it plays all of them instead, which is handy for layering two sounds.

### Record
1. Arm a track with **R** in its header.
2. Optionally choose a **count-in** in the top bar.
3. Press **Record** (or the `R` key).
   - Notes and audio appear on the timeline while you play.
   - Press **Record** again to stop recording and keep playing, or **Stop** to stop both.

### Play guitar or bass through the amp
1. Plug the instrument into your audio interface's Hi-Z / instrument input.
2. Select the **Guitar (Amp)** track (or add one with **+ Audio**), open the **Instrument** tab and click **Enable audio input**.
3. Choose your **Device**, then click the **Channel** whose meter moves when you play.
4. Turn on monitoring with the **I** button in the track header. Use headphones to avoid feedback.
5. Shape the tone in the **Effects** tab or load one of the amp chains. Recordings store the dry signal, so you can change the amp afterwards.

### Edit clips
- **Split** the selected clip at the playhead with `S`, or right-click a clip and choose *Split here*.
- **Rename** a clip by double-clicking its name strip, or with right-click → *Rename…*.
- **Duplicate** with ⌘/Ctrl + D, and **delete** with Backspace/Delete.
- Double-click an empty spot on a MIDI track to create a clip, or a MIDI clip to open it in the piano roll.

### Automate volume or pan
Click **A** in a track header to show its volume lane, and click again for pan. Click the lane to add points, drag to move them and right-click to delete them.

### Tune
Click the tuning-fork button in the top bar. The tuner listens to the selected input channel and highlights the nearest string of the chosen tuning.

## Architecture

```
src/
├── core/    project model and validation, undo/redo store, scheduler, transport, WAV encoding
├── dsp/     audio engine and channel strips, effects, procedural impulse responses,
│            AudioWorklets (saturation, recording), offline renderer, pitch detection
├── synth/   instrument engines and their offline note renderers
├── midi/    Web MIDI input and message parsing
└── gui/     toolbar, track list, timeline and piano roll (Canvas), effects rack, tuner, keyboard
electron/    desktop shell (sandboxed; only requests microphone and MIDI access)
build/       app icon (generated by scripts/make-icon.mjs)
scripts/     icon generator and macOS ad-hoc signing hook
tests/       unit tests: project format, scheduler, synthesis, pitch detection, I/O
docs/        design notes and the project file format
```

### Signal flow

```
Instrument / audio input ─▶ [insert 1] ─▶ [insert 2] ─▶ … ─▶ fader ─▶ pan ─▶ mute/solo ─▶ master bus
master bus ─▶ [master inserts] ─▶ master volume ─▶ safety limiter ─▶ output
```

### How it works
- **Single source of truth.** The project is a plain data object. The audio engine reconciles its node graph with the project after every change, so undo, file loading and live editing all go through the same path.
- **Lookahead scheduling.**
  - A worker-based clock ticks every 25 ms, and each tick schedules events up to 120 ms ahead of the audio clock, in eighth-of-a-beat slices.
  - The slice scheduler is a pure function: real-time playback, offline WAV export and the unit tests all use it.
- **Voices.** Oscillator-based instruments build a small node graph per note that disconnects itself when it finishes, with voice stealing above the polyphony limit.
- **Pre-rendered instruments.**
  - Piano, mallets and plucked strings synthesise each note once into a buffer, using pure, testable functions (`src/synth/render.ts`), and keep it in an LRU cache per pitch and velocity layer.
  - Notes used by the project are rendered in the background, so playback never waits for synthesis.
- **AudioWorklets.**
  - The drive effect runs its non-linear curves on the audio thread, with a WaveShaper fallback.
  - The recorder streams raw PCM chunks stamped with their audio-clock frame, which is what lets takes be drawn live and placed precisely.
- **Deterministic DSP.** Procedural impulse responses and noise use seeded generators, so an exported WAV matches what you heard.

More detail: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (design notes) and [docs/PROJECT_FORMAT.md](docs/PROJECT_FORMAT.md) (file format).

## Building installers and releasing

Installers are built with [electron-builder](https://www.electron.build/) (configuration in `electron-builder.yml`).

**Locally:**

```bash
npm run dist        # current OS
npm run dist:win    # Windows installer + portable .exe (works on macOS too)
```

**On GitHub:** two workflows run in GitHub Actions.

- **`.github/workflows/ci.yml`** type-checks, tests and builds every push and pull request.
- **`.github/workflows/release.yml`** runs when you push a version tag. To publish a release:
  1. Update `version` in `package.json` (for example `0.1.0`), then commit.
  2. Push a matching tag: `git tag v0.1.0 && git push origin v0.1.0`.
  3. The workflow builds and smoke-tests the app on Windows, macOS and Linux, then attaches all installers to a **draft** release.
  4. Review the draft under **Releases** and click **Publish release**.

> **Building macOS installers locally from a cloud-synced folder** (for example a Desktop or Documents folder synced by a cloud-storage service) can fail at the signing step. The sync client adds extended attributes to files, and code signing rejects them. Write the output somewhere else: `npx electron-builder --mac --config.directories.output=/tmp/openband-release`. CI is not affected.

## Known limitations

- **Recording alignment** relies on the latency the browser reports. Some audio interfaces need a small manual nudge of the take.
- **Audio recording ignores the cycle region**: audio takes are linear. MIDI recording does support loop overdubs.
- **Input channels**: browsers usually expose at most two input channels per device.
- **No third-party plug-ins** (VST/AU) and no import of other applications' project files.
- **Desktop builds are unsigned**; see [Download](#download).

## Contributing

Issues and pull requests are welcome. Before opening a pull request:

```bash
npm run typecheck
npm test
npm run build
```

Please keep the project self-contained:

- Sounds must be generated by code.
- Don't add sample libraries, recorded impulse responses or presets copied from other software.
- New DSP or synthesis code should come with tests where practical. The pure renderers in `src/synth/render.ts` and the pitch detector are good examples to follow.
